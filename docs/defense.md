# Как устроен проект

1. Браузер открывает React-интерфейс. В App.tsx хранится состояние формы и списка задач.
2. api.ts отправляет HTTP-запрос через fetch.
3. ASP.NET Core выбирает метод TasksController по адресу и HTTP-методу.
4. TaskInput проверяет название, приоритет, статус, прогресс и длину текста.
5. PlannerDbContext переводит операции EF Core в SQL и работает с SQL Server.
6. Контроллер возвращает JSON. React обновляет экран.

## Основные понятия

- CRUD — создание, чтение, изменение, удаление.
- REST API — адреса ресурсов и HTTP-методы. Здесь GET, POST, PUT, DELETE.
- Dependency Injection — ASP.NET Core передаёт DbContext в конструктор контроллера.
- Миграция — сохранённое изменение структуры базы.
- TypeScript проверяет типы при сборке; серверная валидация всё равно обязательна.
- await не блокирует поток на время ожидания базы.
- AsNoTracking используется для чтения, когда изменения сущности не сохраняются.
- PUT передаёт все редактируемые поля; частичный PATCH сейчас не реализован.

## API

| Метод | Адрес | Ответ |
|---|---|---|
| GET | /api/tasks | 200 и список |
| GET | /api/tasks/{id} | 200 или 404 |
| POST | /api/tasks | 201 и Location |
| PUT | /api/tasks/{id} | 200 или 404 |
| DELETE | /api/tasks/{id} | 204 или 404 |
| GET | /api/health | 200 или 503 |

Некорректные данные дают 400. База не подменяется массивом или localStorage.
Сейчас нет авторизации — это ограничение второго этапа, а не готовое многопользовательское приложение.
